# 0.6.0 透明视频候选与验收边界

0.6.0 已于 2026-09-11 完成本机安装替换。本文保留候选阶段的技术变化与证据；最终安装验收进度以 [0.6.0 安装验收](acceptance-0.6.0.md) 为准。下文的锁屏和待安装描述是之前阶段的历史状态。

## 问题与变化

0.5.1 壁纸 WebContent 的采样栈显示持续 PNG 解滤、解压及 drawImage 工作。每帧解码完整 PNG 并重绘背景的路线虽然保留了生成画面，但持续 CPU 开销偏高。

候选在 macOS 原生端使用系统支持的 HEVC with Alpha，人物成为完整 DOM 视频层，背景不再随每一帧重绘。原来的完整 PNG 帧全部保留，浏览器默认和视频解码失败时使用兼容渲染。运行时没有人工嘴型或牙齿层，也没有新增云服务或上传音频。

Apple 的 [HEVC with Alpha 介绍](https://developer.apple.com/videos/play/wwdc2019/506/)和[官方使用说明](https://developer.apple.com/documentation/avfoundation/using-hevc-video-with-alpha)说明了该格式在 Apple 系统中的支持与预乘 Alpha 语义。实际编码必须先预乘颜色：直接把 straight-alpha PNG 交给当前编码链会在发丝边缘产生白边。首个错误原型已排除。

22 段现有素材各生成两种候选：标准 32 fps、节能 16 fps，均为 560×832、3.5 秒。非原生节奏片段沿用已有时间曲线并离线烘焙；自然静息保持正向节奏。节能切换发生在动作边界，不能跳到当前动作的不同位置。素材版本 1.9.0。

## 原型性能对照

同一独立 WKWebView 窗口、360×535 CSS 人物显示区域，比较同一自然静息片段。逐帧模式复用正式 PortraitPainter，透明视频模式使用系统 DOM video。采样包括该原型的主进程、GPU、网络及 WebContent，100% CPU 表示一个逻辑核。

| 模式 | CPU 合计中位数 | RSS 合计中位数 |
|---|---:|---:|
| 透明视频 A | 7.9% | 60.47 MiB |
| 原始逐帧 | 37.95% | 172.16 MiB |
| 透明视频 B | 8.2% | 56.77 MiB |

原始记录为 `artifacts/video-probe-video-A.csv`、`video-probe-frames.csv`、`video-probe-video-B.csv`；汇总 `video-probe-ab-summary.json`。各段排除前 15 秒；逐帧只采用第 15–65 秒，排除后来并行转码的影响。样本数量不相等（58、10、22）。视频约 31 fps，逐帧约 28 fps。以上是短时同窗口对照，不是正式全屏壁纸、整机 GPU、温度或电池续航结论。

## 素材检查

- 44 个视频容器均核对编码、尺寸、帧数及 3.5 秒时长；逐项记录源清单哈希、选帧序列哈希、成品哈希。
- 两套视频都经 AVFoundation 解码首尾帧，透明角为 0、面部 Alpha 为 1。
- 标准版首帧 Alpha 与共同原始入口逐像素一致；不透明区 RGB 平均绝对误差最大约 1.53/255；视频内首尾预乘颜色平均差最大约 0.87/255。压缩误差不是身份相似度，也不证明所有动作绝对无缝。
- 浏览器实际播放已观察到完整人物、自然随机与说话轮换；浅色背景下发丝透明正常。暂停前后实际媒体时间保持在同一值，恢复后继续；节能模式确认加载 low rendition。

## 播放与恢复

`VideoSequence` 复用既有动作导演，只有媒体真正完成后才推进场景时钟。中途语音请求等待当前动作收势，保留静息间隔与随机不立即重复的规则。两个视频槽位在下一段首帧呈现时原子替换，只显示一个人物，不以人物叠加淡化掩盖衔接。

准备下一段期间，已结束的视频保持最后画面。尤其禁止声音状态更新调用旧视频 play()，否则浏览器会重新播放旧片段。暂停、隐藏预览和休眠停止播放；销毁释放视频与对象 URL，并将诊断归零。超时或解码失败明确切回兼容播放。

## 构建与回归结果

- 74 项 JavaScript 测试、5 项 Rust 测试、Clippy 全目标严格检查通过。
- 最终桌面构建及固定本地证书签名通过；独立候选位于 `artifacts/WallSoul-0.6.0-Candidate.app`，当前 0.5.1 安装和开发包均保留。
- 候选资源逐项哈希与暂存目录一致，2,342 个文件、约 1,191.64 MiB；版本、二进制与清单哈希见 `artifacts/release-candidate-0.6.0.json`。
- 重新加载后的浏览器连续验收为 175 秒、700 次 250 毫秒采样，覆盖全部 22 段，42 次片段切换，采样中可见层重叠与空缺均为 0，未观测到媒体时间保持不变。见 `artifacts/video-sequence-browser-0.6.0.json`。这是 DOM/媒体时钟检查，不是逐帧光学无缝证明。开发热更新期间的旧 React 根节点警告不计入此次重新加载后的记录；实验页现已在 HMR 销毁时释放 React 根节点，避免再次重复创建。

## 原生验收追加发现

原生窗口恢复后，候选确认以 1440×900 桌面层播放，标准约 30 fps，节能约 14–16 fps。实际应用输出测试触发“轻声交谈 A”，声音结束恢复静息，停止采集后两路电平归零；暂停时桌面 fps=0，源帧编号保持不变。

验收发现并继续修正三项问题：半身素材底部在桌面留白，现加入仅完整桌面帧使用的贴底布局；系统预定义 Quit 路径出现未正常退出提示，改用统一清理的菜单动作并增加“打开幕灵”；音频来源和阈值随面板卸载丢失，现接入原有持久设置队列，旧配置迁移默认 -38 dB，保存偏好不会自动开始采集。上述追加修复的最终候选仍需原生复核。

最终候选已重新构建并签名，74 项 JavaScript、5 项 Rust 和全目标 Clippy 检查通过，资源哈希已再次核对。原生操作工具随后再次报告锁定，因此最终菜单退出/重启偏好复核、安装替换和安装版 30 分钟长测仍未完成。应用已正常退出，running 标记不存在，临时低功耗开关在确认无幕灵进程后恢复为测试前的标准模式；本地测试音页面已关闭。安装版仍为 0.5.1。

## 解锁后的最终安装复核

最终候选菜单退出清理、关闭窗口后恢复面板、音频偏好重启保存通过。已安装至 `/Applications/幕灵.app`，原安装包保留备份；安装后全部 2,344 个 Resources 文件与签名候选逐一哈希一致（包含签名打包元数据，故比前端暂存资源数多 2 个）。最终安装版本地测试音触发轻声交谈 C，结束恢复自然静息；停止后电平清零，恢复豆包来源并导航后保持。暂停超过 45 秒帧计数不变，恢复后低功耗约 15.6 fps。30 分钟长测正在进行，尚未作最终持续运行结论。
