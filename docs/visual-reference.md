# 2026-09-09 用户视频：视觉验收标准修正

用户明确说明这段视频才是目标效果。参考源为本地 `2026-09-09 20_46_42.mp4`，25.33 秒、1024×576、30 fps。只作为视觉参考，不把它或抽帧当作可实时交互的角色包。

## 已观察到的效果

- 精致的三维风格年轻女性半身人物，短发、服装与面部有材质/光照层次。
- 人物占据桌面约一半以上高度，是桌面视觉主体；深蓝至洋红色简洁背景，桌面图标和任务栏在上方。
- 0–6 秒：托腮、眼神转向、眨眼、微笑；随后从托腮姿态过渡到自然半身站姿。
- 8–18 秒：口部、眼睛、头颈和肩膀共同运动；并非只有一张图片上下浮动。
- 19–22 秒：人物下蹲到画面底部，再起身。
- 22–25 秒：双手整理头发、表情变化、眨眼和头部转向。
- 左下方出现音频播放/波形界面，但视频本身不能证明音频来源、实时豆包对话、实时口型同步或鼠标跟随的实现方式。

## 对当前版本的影响

当前 Canvas 2D 小幕/阿澄只用于桌面宿主、资源加载和状态机制验证，**没有达到用户的角色视觉验收标准**，不可将基础版作为最终效果交付。

保留 Tauri 共享工程、平台边界、桌面窗口、权限/联动能力模型和 Rust 唯一会话状态。高质量表现层需使用具备面部/骨骼绑定与动作的原始 3D/VRM/Live2D 资产，或明确标注为预渲染的干净动画资源。收到资产后决定最小可行渲染方式，不仅凭视频宣称实现了相同三维模型。

原始素材未取得时，不将桌面录屏裁剪循环伪装为最终数字人物；不把演示口型认作真实豆包同步；不继续以小卡通风格为最终视觉方向。

## 后续验收

1. 人物精细程度、桌面占比、镜头构图和背景接近参考。
2. 眼睛、头颈、肩膀、手臂有连续自然动作，能稳定从各动作回到待机。
3. 支持素材真正具备的动作；不存在的动作不使用假按钮。
4. 对话动作由真实能力信号驱动；没有信号则保持自然待机，演示操作明确标记。
5. 完整保留图标、鼠标穿透、菜单栏/独立面板、暂停/恢复、屏幕适配与性能控制。

## 用户追加授权与当前实现

用户随后明确要求由开发方自行生成素材，无原始素材。已调用内置 imagegen 生成新的高质量半身人物和四套变体，并集成通用 2.5D 合成器。用户不再需要为这版提供图片。新的视觉质量已在实际浏览器预览确认；完整三维骨骼、连续下蹲起身和任意角度转身仍未实现，不能把静态姿态变体的短过渡视为这些动作已完成。
