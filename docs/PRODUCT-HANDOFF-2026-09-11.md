# 幕灵 WallSoul：产品要求、体验目标与技术交接

整理日期：2026-09-11。当前工作目录：`/Users/jared/Desktop/app/WallSoul`。

本文面向接手项目的产品、交互、图形动画与桌面软件开发模型。依据用户原始需求、后续明确变更、历次实测反馈及当前工程核查整理。**后续明确要求优先于原始提示词；现有实现不是最终产品定义；测试通过不等于用户验收通过。**

## 1. 产品最终目标

幕灵是一个以写实人物为核心的桌面陪伴应用。人物融入桌面场景，在用户使用电脑时安静、自然地存在；用户与官方豆包进行语音交流时，幕灵根据麦克风输入与豆包输出声音，呈现合理的聆听、说话和表情反应。

核心感受应当是：**同一个人在桌面上持续存在，平时安静站立，有微小的自然活动，交谈时给予反馈。**不能让用户感觉自己在观看一组互不相干的视频、不断重置姿态的动画，或被缩放、拉伸的静态照片。

用户明确允许长期打磨，不要求赶工，曾表示可以花一整天优化，要求成品至少达到其主观标准的 75 分后交付。这是质量门槛，不是已经获得的评分。当前不能宣称产品已达到该门槛。

首发为 macOS，优先 Apple Silicon，初始系统目标 macOS 14+；后续考虑 Windows 11 x64。必须保留共享工程和平台适配边界，避免双端分别维护两套产品。

## 2. 最重要的路线变更：必须遵循当前要求

| 主题 | 曾经讨论或尝试 | 当前有效要求 |
| --- | --- | --- |
| AI 回答 | 内置模型、模型 API、本地语音对话 | 幕灵不内置对话 AI，不生成回答。理解、回答和语音输出由官方豆包承担。 |
| 豆包联动 | 探测并自动控制豆包桌面版通话 | 用户已明确取消这条路线。幕灵分析用户麦克风和豆包应用输出声音，不接管豆包通话界面。 |
| 人物形象 | 演示人物、3D/动漫人物、静态图替代 | 保留用户认可的原生成写实人物，不能擅自换脸、换画风或换成简化模型。 |
| 动画技术 | 实时面部变形、嘴唇贴片、人工牙齿、3D 面部实验 | 用户因不自然而放弃该路线，要求多段 AI 小视频承担说话、动作和表情表现。 |
| 说话露齿 | 曾要求完全不露牙齿 | 后续明确允许自然说话时微微露齿。重点是嘴巴开合小、嘴唇牙齿下颌协调，不是强制无齿。 |
| 随机模式 | 大量状态不触发；后来改为紧接着播放所有状态 | 全部状态应有机会出现，但不能高频表演。明显动作之间要有自然静息。 |
| 静息 | 定格初始图、用聆听片段填充 | 要“人物无明显动作，但不僵硬”的真实静态，保留微小生命感。 |
| 交付 | 浏览器实验页和开发预览 | 必须提供可运行安装版，在实际桌面环境验收。实验页不能代替成品。 |

“不内置 AI”针对运行时对话能力，**不禁止开发阶段使用 AI 制作人物与动画素材**。不要把这两件事混淆。

## 3. 人物身份与美术一致性：不可牺牲的要求

### 3.1 保留原形象

- 以项目中用户已认可的人物参考为身份依据，不能自行另选新人物。
- 保持脸型、五官比例、眼神风格、肤色、发型、服装、身体比例、光照和整体气质一致。
- 用户接受的外观是写实年轻成年女性、短黑发、黑色长袖上衣；最终判断以实际参考素材为准，文字描述不能取代参考图。
- 新动作必须像“同一个人做动作”，不是“相似的人出现在另一个片段”。
- 允许研究 3D、专业动画软件或其他工具，但不能因此直接更换最终呈现。任何路线替换应先证明形象和观感确实更好。

### 3.2 一致性不只是分辨率相同

所有动作、表情、说话、聆听、静息和过渡必须具有尽量一致的：

- 实际细节与清晰度，特别是脸、头发、牙齿、手指及衣物纹理。
- 人物位置、大小、相机视角、透视和镜头距离。
- 色温、曝光、肤色、轮廓光及背景融合效果。
- 帧率、运动速度、压缩观感与采样质量。

历史反馈包括“撩头发时变模糊”“动作结束回到初始状态时清晰度变化”。统一成 560×832 或统一文件格式不能证明问题已解决；将低清素材放大也不等于恢复细节。

### 3.3 头发与透明边缘

- 发丝边缘不能出现绿色残留、硬切边、明显锯齿、半透明脏边或前后不一致的轮廓。
- 头发不能像被直线剪掉，不能在转头时出现缺口、漂浮区域或重影。
- 抠像不能以大量侵蚀人物轮廓为代价，尤其不能误删黑衣、手臂及细发丝。
- 需要检查静止帧和连续运动，不能只用一张截图宣布全部发丝问题解决。

## 4. 动作与静息体验

### 4.1 丰富，但不是一直表演

用户先后要求更多动作、更多表情、随机变化及随情绪变化，随后明确反馈“整体动得太频繁”。两者并不矛盾：

- 动作库要丰富，长期观看不会只出现少数动作。
- 时间分配应以安静陪伴为主，明显动作偶尔发生。
- 不要把“随机”实现成不断掷骰子切换状态，也不要把每个动作都等频高频播放。
- 当前 12–20 秒静息间隔是最近实现的调节值，不是用户规定的最终标准，可依据体验验证继续调整。
- 应避免机械周期感、相邻动作重复、情绪突变和不合场景的动作组合。

### 4.2 自然静息是专用行为

用户原话：“在每个动作之间增加一个人物无动作但是不僵硬的过渡，拟真的正常人真实静态。”

有效目标：

- 身体大体稳定，嘴唇自然闭合，双手放松。
- 仅保留轻微呼吸、自然眨眼、极小的重心或姿态调整。
- 不是持续点头、歪头、微笑、抬手，也不是假装说话。
- 不冻结成一张图，不靠整张图片周期性缩放冒充真实呼吸。
- 眨眼、呼吸和微动不能有明显循环节拍；是否需要多个静息变体应以真实观感决定。

### 4.3 动作完整性

- 挥手、整理头发及附带抬手的表情必须完整显示手掌、手指、前臂和手肘。
- 超过显示范围时，应合理适配人物大小或显示区域，不能直接切断肢体。
- 必须区分：原始生成视频出框、抠像误删、画布边界、布局缩放、窗口裁切。各问题需要不同修复方式。
- 原视频没有生成出来的手臂，扩大画布或缩小人物无法补回。
- 当前人物是半身素材，不应声称已具备完整全身动作。

### 4.4 衔接是当前最高优先级

用户多次反馈每个动作之间有明显割裂感，最新一轮反馈仍是“衔接不够流畅”。后续模型应将此视为**尚未验收通过的核心问题**。

衔接需同时满足：

1. 空间连续：脸、头、肩、手臂、躯干不能瞬移，人物不能突然变大或变小。
2. 运动连续：速度和方向合理变化，避免骤停、突启、突然倒放及机械回正。
3. 视觉连续：清晰度、纹理、曝光、发丝轮廓和抠像不能突然变化。
4. 状态连续：动作要有自然收势，不能识别到用户说话就瞬间切成另一种姿态。
5. 播放连续：解码、预加载、掉帧、后台节流不能制造冻结后跳帧。
6. 人体合理：过渡不能产生双手、双嘴、透明人脸、错位牙齿或形变融化。

首尾图哈希相同，仅能证明两个端点相同；不能证明这两个端点前后的运动、细节和速度连续。统一首尾姿态、缓入缓出、光流或交叉淡化都只是手段，不能代替动态验收。

## 5. 表情要求

用户明确要求十组：**喜、怒、哀、乐、兴奋、幸福、眉眼、脸红、害羞、生气**。

- 每组应有可辨认、合理的表情差异，不能只改名称。
- “喜”和“乐”、“怒”和“生气”等相近状态应体现不同程度或表达方式，保持整体人物气质。
- 不要把表情做成大幅摇头、无关挥手或夸张舞台表演。
- 脸红应自然，眉眼应有实际眼部表现，但不宜夸张。
- 用户要多状态随机组合，但组合需要过渡和情绪逻辑，不能上一秒幸福、下一秒无缘由愤怒。
- 音频情绪只能按实际分析能力呈现。只用音量和节奏时，不得宣称理解了语义情绪。

## 6. 说话动画要求

### 6.1 最终选定路线

使用多段同一人物的 AI 说话小视频，根据真实豆包音频进入说话状态，在说话过程中轮换小视频，并自然循环、收尾和退出。

### 6.2 视觉标准

- 嘴唇开合克制，正常轻声交谈感，不能夸张张嘴或露出整排牙齿。
- 微微露出自然牙齿可以接受；笑时可以露出洁白整齐的牙齿。
- 上下唇、牙齿、下颌、下巴和脸部要协调，不能只动嘴唇、牙齿像固定贴图。
- 禁止多个嘴叠加、嘴部漂移、双重牙齿、灰色方块牙、塑料牙及贴纸感。
- 不要恢复已经被用户否定的人工牙齿/实时局部嘴型路线来冒充已解决。

### 6.3 同步含义

- 真实声音开始后及时表现说话；停顿时合理收口或短暂保持；结束后自然退出。
- 当前小视频方案不是精确音素驱动。需要准确描述为“随声音的近似说话表现”，不能承诺逐字对口型。
- 如果后续研究更准确的同步方案，应先验证身份一致性、自然度、时延和资源消耗，再决定是否引入。
- 不能把麦克风输入、音乐或其他应用的声音错误当作豆包回复。

## 7. 聆听与声音交互

用户明确要求“识别到用户说话时，眼睛要看着用户”。这里指面向屏幕前方的视觉注视；无需为此擅自增加摄像头采集。

- 用户麦克风有语音活动：进入聆听，保持自然注视与合理小反应。
- 豆包目标应用有语音输出：进入说话表现，可按实际能力映射语气表情。
- 安静时：进入自然静息和低频陪伴动作。
- 聆听不能一动不动，也不能只有一种；用户要求在原有基础上再增加三种，即至少四种可区分、自然轮换的聆听状态。
- 状态切换需要防抖、停顿容忍和合理收势。保持及时响应与动作连续之间的平衡。
- 同时检测到用户与来源声音时，处理扬声器回声和串音；不能在说话/聆听之间疯狂抖动。
- 保持真实状态与演示、手动动作之间的区别。随机表演不代表豆包真实通话状态或真实情绪。

当前自然随机池还包含说话和聆听表现，这是为满足此前“所有状态随机触发”而做的实现。**是否应允许安静环境出现无声说话，是需要明确评估的体验冲突，不应把当前实现当成用户最终认可的语义。**建议接手模型优先提出兼顾全动作可见性与真实声音语义的组织方式。

## 8. 桌面软件与用户体验要求

- 需要真正的桌面层壁纸，不能用置顶大窗口或独立全屏 Space 冒充。
- 普通窗口、桌面图标、双击、右键、框选、文件拖放、Dock 和菜单栏正常使用。
- 壁纸默认鼠标穿透、不抢焦点；通过菜单栏与独立面板操作。
- 提供预览、设为壁纸、屏幕选择、人物位置和大小、暂停、恢复、停止壁纸和退出。
- 停止壁纸应露出用户原桌面，不修改原壁纸，不强制重启 Finder/Dock。
- 支持目标屏幕变化、缩放与高 DPI；验证外接显示器断开、Spaces、Mission Control、Stage Manager、全屏应用和睡眠恢复。
- 壁纸暂停、音频采集停止、豆包通话结束是不同状态，界面不能混淆。
- 普通界面使用清楚中文，错误提示给出下一步操作；技术细节进入诊断页。
- 能力失败不能悄悄变成演示成功；未知状态如实显示。
- 避免“安静待机”“自然静息”“自然随机”等近似入口让用户困惑，需要重新整理命名、含义和默认行为。
- 首版不需要账号系统、支付、商城、云同步或自动下载角色商城。优先做好现有体验。

## 9. 性能、隐私与权限

用户曾明确反馈运行幕灵后电脑严重发热，性能是验收目标，不能为视觉效果无限堆积实时计算。

- 初始目标约 30 fps，并有低功耗模式；当前具体帧率应以实际测量为准。
- 控制 CPU/GPU、内存、解码缓存、并发资源请求、后台轮询与可见窗口数量。
- 不要同时让面板预览和壁纸重复执行昂贵计算而不测量成本。
- 暂停、不可见、锁屏、睡眠和退出后及时降低或停止无用工作。
- 音频采集仅用于用户开启的本机声音跟随，不保存、不上传原始音频，不擅自收集账号、聊天记录或摄像头画面。
- 不读取豆包账号库、Cookie、密码、聊天数据库来恢复已取消的自动化路线。
- 运行时权限按实际用途申请，清楚说明；用户希望减少反复授权，但应用不能替操作系统保证永久授权。
- 保持稳定应用身份和签名，避免每次测试都变成不同应用身份。系统权限弹窗不能绕过。
- 锁屏、睡眠和退出后的采集状态要可信，恢复后不能擅自重开麦克风或豆包通话。
- 资源包只允许数据与素材，校验版本、路径、尺寸和容量，禁止任意脚本、路径越界与任意文件读取。

## 11. 接手后的工作优先级建议

以下是交接建议，不是用户已经指定的具体算法。

### P0：先复现并解决核心观感问题

1. 用当前安装版连续录制动作、静息、声音打断和恢复，标出用户能看见的接缝时间点。
2. 分别定位素材差异、离线端点变形、时序调度、缓存解码、窗口节流和布局问题。
3. 检查所有声称“聆听/静息”的实际素材，是否含张嘴、过大头动或不适合语义的表演。
4. 建立一致的姿态、构图、光照与清晰度标准，再决定复用、修复或重新生成哪些素材。
5. 优先处理脸、头发、嘴和手臂，任何明显双影、截断和变脸都应阻止交付。
6. 不要只继续叠加短过渡、延长等待或放慢动作，必须证明割裂的根因确实得到改善。

### P1：行为与声音体验

1. 建立静息为主、动作有节奏、声音响应及时的行为组织。
2. 检查手动动作在当前动作收势后是否按用户意图执行，是否被静息计时错误延迟。
3. 检查解码驱动时钟在高负载或低功耗时是否导致人物跟随声音显著滞后。
4. 优化麦克风触发阈值、输出检测、回声抑制、短停顿、防抖及来源丢失恢复。
5. 整理模式命名和状态提示，避免把随机说话动画误读成真实豆包正在回答。

### P1：稳定性与性能

1. 实测前后台、预览与壁纸并存时的 CPU/GPU、内存、帧率和发热。
2. 连续运行至少 30 分钟，观察资源增长、重复打开面板、设备变化和睡眠恢复。
3. 验证暂停、停止、退出确实释放渲染和采集资源。

### P2：在核心体验通过后扩展

- 更多合格动作、静息变体和情绪表达。
- 角色包和平台适配完善。
- Windows 实际开发与独立验收。
- 不应优先增加商城、账号、复杂插件系统等与当前体验无关的功能。

## 12. 建议验收矩阵

| 维度 | 必须检查的场景 | 不可接受的结果 |
| --- | --- | --- |
| 身份一致 | 各段脸部连续与并排对比 | 换脸、年龄气质漂移、头型比例变化 |
| 清晰度一致 | 静息→动作→静息，特别是整理头发 | 突然变糊、突然变锐、纹理跳变 |
| 肢体完整 | 挥手及所有抬手表情，窗口与位置极值 | 手掌、手肘、前臂被直线切断 |
| 毛发边缘 | 深浅背景、转头、抬手经过头发 | 绿边、硬切、脏边、头发缺口 |
| 接缝流畅 | 每段进入和退出静息；说话与聆听切换 | 瞬移、倒放突变、双影、冻结后跳帧 |
| 安静感 | 无输入连续观看数分钟 | 持续点头、张嘴、固定周期表演 |
| 说话自然 | 长句、短句、停顿、结束 | 大张嘴、牙齿固定、叠嘴、明显延迟 |
| 聆听自然 | 用户说话、打断动作、连续发言 | 立刻跳姿态、眼神不朝向用户、只剩一张静态图 |
| 音频真实性 | 来源独立播放、麦克风讲话、同时发声 | 麦克风被当成豆包输出、背景音乐误触发不透明 |
| 桌面可用性 | 图标、右键、拖动、Spaces、外接显示器 | 抢焦点、遮挡操作、独立全屏代替壁纸 |
| 生命周期 | 暂停、锁屏、睡眠、权限撤回、退出 | 采集状态不可信、资源残留、擅自重开麦克风 |
| 性能 | 正常与低功耗、前后台、至少 30 分钟运行 | 持续高负载、明显发热、内存单调增长 |

测试结果应区分：自动测试、静帧检查、连续录像检查、真实声音端到端验证、用户主观验收。必须注明实际完成了哪一级。不要给每个维度随意填“通过”。

如需量化评分，可先与上述维度对应提出评价方法；用户的“75 分”不应被转换成只看测试数量的自动合格线。明显变脸、双嘴、截肢或高频跳姿态应作为阻断项处理。
