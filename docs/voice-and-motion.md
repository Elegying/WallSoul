# 幕灵 0.3：原形象、行为与本地对话

## 同类项目与实际采用范围

- [AIRI](https://github.com/moeru-ai/airi)：参考独立的角色表现、对话与平台适配分工；没有把它的 VRM 人物替换进幕灵。
- [Open-LLM-VTuber](https://github.com/Open-LLM-VTuber/Open-LLM-VTuber)：参考本地 ASR → LLM → TTS、打断与角色表达的闭环。本项目采用自身 Rust 权威会话和 macOS 原生音频实现，没有直接移植其服务。
- [LivePortrait](https://github.com/KlingAIResearch/LivePortrait)：实际使用已有官方基础模型和算术表情控制，离线生成原角色的微笑、好奇、关切、眨单眼、移开视线和点头。不加载 InsightFace 权重，不在桌面帧循环运行神经网络。
- [PyMatting](https://github.com/pymatting/pymatting)：实际用于离线 alpha 估计与前景颜色估计。只在边缘不确定区域处理，保留脸部和衣服主体颜色。
- [RobustVideoMatting](https://github.com/PeterL1n/RobustVideoMatting)：调研其时序抠像思路，未集成，不能把它的效果算作本版能力。
- [火山引擎官方实时语音方案](https://www.volcengine.com/docs/6348/1902994?lang=zh)：需要独立开发者鉴权与服务配置，不等于已登录的豆包客户端通话。本版没有调用此付费服务。

## 本地对话

安装在本机的 Ollama 运行 `qwen2.5:1.5b`。只绑定 `127.0.0.1:11435`，设置 `OLLAMA_NO_CLOUD=1`；Rust HTTP 客户端禁用代理与重定向。不会使用账号 Cookie 或私有豆包协议。模型不是豆包，不能继承豆包的声音和记忆。

启动应用后，文字输入 → 本地模型 → macOS 中文系统声音；点击“开始本地语音”后才申请麦克风和语音识别权限。中文识别必须支持 `requiresOnDeviceRecognition`，不可用时明确退回文字输入，不上传录音。语音回复后自动继续聆听，停止/打断结束采集和播放；不支持在系统播音同时全双工识别，避免声反馈。单轮最多采集 30 秒，静默后提交，初次无声音 25 秒超时。

响应正文与最近 4 轮上下文只存在内存，不写运行日志；系统合成语音临时文件播放结束或取消后删除，不保存用户录音。退出后不保留对话记忆。停止后取消本机 HTTP 等待并丢弃迟到结果；模型服务自身是否立即停止内部运算由 Ollama 实现决定。

嘴型强度来自 AVAudioPlayer 的实际播放电平，不是随机伪造豆包讲话。当前是音量驱动张合，尚未达到逐音素口型；眼神和情绪是角色表达，不能诊断用户心理。全身连续骨骼、发丝物理与真实 3D 网格尚未完成，当前是保持原生成身份的神经头像动作加半身合成。

复现本地模型环境：

```sh
brew install ollama
OLLAMA_HOST=127.0.0.1:11435 OLLAMA_NO_CLOUD=1 ollama serve
# 另一个终端
OLLAMA_HOST=127.0.0.1:11435 ollama pull qwen2.5:1.5b
```

应用会在找不到本机服务时启动已安装的 Ollama，不设置登录自启动，只结束自己启动的服务。模型约 1 GB，未包含在应用包中；当前开发机器已经安装。另一台 Mac 需单独安装模型。模型和系统离线语音包的可用性在开始时检查。

## 豆包模式边界

豆包联动继续使用官方签名身份校验和只读辅助功能观察。没有确认说话信号就不生成同步口型；不会接管或挂断用户手动开始的通话。检测到豆包通话时拒绝/停止本地语音；辅助功能未授权时不能保证知道豆包是否正在通话，因此开始本地对话前需要用户自行结束豆包通话。辅助功能权限与麦克风/语音识别权限是三个独立的系统授权。

## 动作素材与资源

保留原图、原脸和短发黑毛衣。基础动作抽取 40 帧，加 6 组各 10 帧表情，共 100 帧。运行时混合相邻帧并柔和切换动作，随机动作不立即重复，回复情绪优先；手动动作按钮可以循环检查对应片段。

4 张 4096×2048 图集，原始 RGBA 解码约 128 MiB/渲染实例，加其他图像和合成缓冲；面板和桌面同时显示会重复占用资源。这不是游戏级实时全身渲染，帧插值也不能补足没有生成的几何细节。低功耗模式保留 15 fps 目标，暂停冻结动画时间。发梢有源图灯光染色，不能把它描述为已生成单根 3D 发丝。

## 未采用的身体动作试验

本地评估了作者官方 [Thin-Plate Spline Motion Model](https://github.com/yoyo-nb/Thin-Plate-Spline-Motion-Model) 的 TED 模型。351 MB 权重通过作者公共下载目录的 SHA-256 校验，使用 `weights_only=True` 载入。用户参考视频仅在本机读取，没有上传。8 帧样片出现严重脸部重影、手部和头部形变，质量不合格，未纳入发布目录。源码与实验输出保留，方便审查；不把它记作已实现的身体动画。

2026-09-10 用户对此前具体说明的上传明确授权后，已将本项目生成的 neutral.png 上传至 Hugging Face `kulkas2pintu/wan555` 免费匿名演示。没有上传用户参考视频、录音或账号信息，没有使用令牌或付费。得到 3.5625 秒、16 fps 的整理头发样片，经抽帧检查后采用；请求及原片保存在 assets-source/body-motion-experiment/wan。

身体动作经离线发丝抠像处理，57 帧以 384×576 的矩形帧存入两张图集，新增原始 RGBA 解码约 54 MiB/实例。动作包含抬手、触发梢、放下手和肩部联动。自然模式间隔 22–46 秒触发，手动选择播放一次；暂停冻结，讲话立即切回声音驱动口型。仍是预生成半身动作，不是任意姿态的实时 3D 骨骼，不声称游戏级发丝物理或手指精度。

## 后台控制

菜单栏分别提供停止本地语音与暂停壁纸。语音阶段会显示聆听、思考、回答等提示；锁屏/睡眠通知直接中断平台音频，并通过中断编号使迟到回复失效。恢复后需要重新主动开始。授权等待超过 60 秒会结束当前启动请求，用户稍后完成授权也不会悄悄开始录音。

点击“清空本次对话”会停止音频并清除内存中的上下文、当前输入转写和回复。普通“停止”保留本次内存上下文，方便稍后继续；退出进程后全部清空。

## 本轮语音设备排查

系统设置曾确认候选包语音识别权限开启，应用实际进入 listening；扬声器测试句未成功转写，未记为闭环通过。默认输入为 MacBook Air 内建麦克风，输出为内建扬声器。原输出约 2%，测试时临时提高两个步进后已降低两个步进恢复。修正版增加输入电平与无信号/有声音未识别的区别提示。重建的 ad-hoc 包再次出现系统授权等待，需要完成系统弹窗；不能以全局授权文字代替 macOS 实际权限。

## 后续拟真调度改进

身体图集支持多个带名称、帧区间、时长及适用情绪的片段，保留旧单片段角色包兼容性。自然模式避免连续重复，可在原时长基础上使用 0.90–1.06 倍速度，动作之间保留 18–38 秒休息。手动选定片段结束后休息 5 秒再播放，便于观察。情绪改变时先完成当前动作，真实说话则立即退出身体动作，由实际声音驱动口型。

当前发布素材仍只有整理头发一组身体片段，新增片段尚未生成；不要把多片段支持或测试夹具中的挥手数据当作已新增挥手素材。本轮针对新样片的外部上传被自动审批拒绝，复核既有授权后仍被拒，等待用户对具体图片与目的地再次确认。没有绕过拒绝上传。

浏览器预览可收起控制面板，避免遮住肩臂；选定动作时自动返回待机姿态。原人物预览移除了两个静态姿态按钮，避免与连续身体动作混淆。

## 单轮、连续对话与句尾处理（2026-09-10）

本地语音可取消“回答后继续聆听”进入单轮模式；默认连续模式在回答播放结束后重新聆听。聆听中点击“说完了”会停止采集，最多等待 0.8 秒补齐识别结果再提交。自动断句要求转写停顿 1.8 秒、声音停顿 1.1 秒同时满足，单轮采集硬上限 60 秒。声音判断为固定能量阈值，噪音环境下仍可能延迟或误断句，不等同于声学 VAD 或识别准确率保证。

中文输入法组合输入时，回车确认候选字不会提交表单。断句纯逻辑回归可执行：

/tmp/wallsoul-endpoint-test
